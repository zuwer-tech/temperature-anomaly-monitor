# Стабильная версия v1.0.0

Тег `v1.0.0` отмечает первую полностью завершённую учебную версию проекта:
все обязательные задачи дорожной карты закрыты, презентация готова, а CI
успешно проверяет код, документацию и структуру PPTX.

Тег ставится на merge-коммит PR #38 только после успешного повторного запуска
GitHub Actions на `main`. Это похоже на опломбированную контрольную пробу:
в любой момент можно вернуться к точно тому же составу проекта.

## Как проверить тег

```bash
git fetch --tags
git show --no-patch --decorate v1.0.0
git rev-parse v1.0.0^{commit}
```

SHA из последней команды должен совпадать с commit, указанным на странице
релиза/tag в GitHub.

## Как восстановить проверенную версию

```bash
git fetch --tags
git switch --detach v1.0.0
pip install -r requirements.txt -r requirements-dev.txt
python -m pytest -q
```

Detached HEAD подходит для проверки и воспроизведения. Для собственных
изменений создайте новую ветку:

```bash
git switch -c experiment/from-v1.0.0
```

## Что входит в контрольную точку

- исходный код правил, ML-инференса и дашборда;
- тесты и GitHub Actions;
- синтетические и демонстрационные данные, отслеживаемые Git;
- технический отчёт, презентация и демо-сценарий;
- схемы признаков, пороги правил и документация.

## Ограничение воспроизводимости

Папка `models/` не содержит обученные `joblib`-файлы в Git. Поэтому
baseline гарантирует версию кода, схемы и данных, но модельные артефакты нужно
воспроизвести командами из README и проверить их совместимость по
`model_meta.json`. Анализируемый CSV нельзя использовать для скрытого
переобучения.

## Почему тег не перемещают

`v1.0.0` — неизменяемая контрольная точка. Если после неё появятся новые
возможности или исправления, создаётся новый тег, а старый не переносится.
