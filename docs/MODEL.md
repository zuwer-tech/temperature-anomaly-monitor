# Модель и правила обнаружения

Обнаружение — два слоя: правила (объяснимые) + Isolation Forest (ИИ).

## 1. Правила (rule-based)

Реализованы в `anomaly_detection.detect_anomalies()`, пороги — в `RULE_PARAMS`.

| Событие | Условие | Уровень |
|---|---|---|
| Потеря сигнала | `is_missing == 1` | Medium |
| Резкий скачок температуры | `abs_temp_diff > sharp_jump_diff` (5 °C) | High |
| Сильное отклонение от нормы | `abs_z_score > z_score` (3) | Warning |
| Зависание датчика | `is_stuck == 1` (точное равенство подряд ≥10) | Medium |
| Отклонение от группы датчиков | `abs_diff_from_group_mean > group_deviation` (8 °C) | Warning |
| Устойчивый перегрев | наклон `rolling_mean` по окну 20 > `overheat_slope` (0.12) | Warning |

`is_stuck` считается в `preprocessing.py` через **точное равенство** подряд
`STUCK_MIN_RUN` значений (а не порог `|Δt|<0.05`). Это важно: пороговый
критерий ловил ступени квантования АЦП реальных данных как «зависание»
(тысячи ложных тревог).

`abs_z_score` считается по **скользящему** `rolling_mean/rolling_std`
(локальный z-score), а не по глобальному среднему датчика. Глобальный на
растущем реальном сигнале ловил весь верхний полубас как аномалию.

## 2. Isolation Forest

- Обучается **только на ранних строках `scenario == 'normal'`**
  (`train_model.train()`), чтобы учить штатный режим, а аномалии становились
  «нетипичными».
- Сохраняется: `models/scaler.joblib`, `models/iforest.joblib`,
  `models/model_meta.json`.
- `detect_anomalies()` загружает сохранённую модель (`transform`/`predict`,
  без `fit`). Для анализа обязательны оба артефакта: `scaler.joblib` и
  `iforest.joblib`. Если хотя бы одного из них нет, анализ завершается
  `ModelNotTrainedError` с командами для предварительного обучения.
- `contamination` (доля аномалий) по умолчанию 0.04.

### Независимая по строкам временная оценка

Для текущего синтетического benchmark используется фиксированная граница
`2026-06-06 14:00:00`:

- train: `timestamp < 14:00` и `scenario == 'normal'` — 720 строк;
- evaluation: `timestamp >= 14:00` — 2160 строк, включая 1580 normal и
  580 anomaly;
- пары `sensor_id + timestamp` из train и evaluation не пересекаются;
- все шесть датчиков и все семь аномальных сценариев остаются в evaluation.

Признаки сначала рассчитываются на полном временном ряду, отсортированном по
`sensor_id, timestamp`, и только затем применяются маски train/evaluation.
Так первые evaluation-строки используют реально доступную прошлую rolling-
историю train, а окна не сбрасываются искусственно на границе. Rolling-операция
в `prepare_features()` смотрит только на текущие и прошлые строки, поэтому
будущие evaluation-значения не меняют признаки train.

Это независимая по строкам train/evaluation оценка внутри одного текущего
синтетического benchmark. Она не является полностью независимой от процесса
разработки признаков и порогов и не заменяет валидацию на производственных
данных.

Модель должна быть обучена заранее на отдельном штатном baseline. CSV, который
передан для анализа, используется только для `transform`, `predict` и
`decision_function`: обучение на нём исказило бы норму и создало data leakage.

### Аномалия только по ИИ

Если Isolation Forest помечает точку как аномальную, а правила — нет, ей
присваивается тип «Нетипичное поведение по ИИ-модели». Это полезно для ловли
тонких отклонений, которые не описаны правилами (например, медленный дрейф
датчика — его наклон ниже пика нормальной синусоиды, правилом от нормы не
отделить, но ИИ ловит).

## 3. Объединение

```
final_anomaly = (rule_anomaly == 1) | (iforest_anomaly == 1)
```

Уровень риска уточняется по `anomaly_score_norm`:
- > 0.85 → High;
- 0.60–0.85 → Medium (если ещё не выше).

## 4. Метрики (бенчмарк)

На полном синтетическом benchmark после временного разбиения:

| Слой | Precision | Recall | F1 | FP на evaluation normal |
|---|---:|---:|---:|---:|
| Isolation Forest | 0.6681 | 0.5483 | 0.6023 | 10.0% |
| Правила + Isolation Forest | 0.6648 | 0.6293 | 0.6466 | 11.65% |

Метрики рассчитаны только на 2160 evaluation-строках. Старый регрессионный
floor precision для Isolation Forest `0.70` заменён на `0.66`; floor F1
`0.45` сохранён. Для полного пайплайна старый floor FP `< 5%`, рассчитанный с
пересечением train/evaluation, заменён на `< 12%`; floor F1 `>= 0.60`
сохранён. Модель, признаки, правила и их пороги при этом не менялись.

На реальных `Т2.csv` (после объединения с `mod_AI_2`): 94% ложных тревог → 10%.

## 5. Обучение

Правильный порядок локального запуска:

```bash
python Data.py
python preprocessing.py
python train_model.py
python anomaly_detection.py
```

Первые три команды создают baseline, признаки и сохранённые артефакты модели.
Только после этого четвёртая команда анализирует данные, не переобучая модель.

В Google Colab — `notebooks/train_model_colab.ipynb` (пошагово, для новичков).

Альтернативы готовых моделей для дальнейшего развития — в соответствующем
issue (PyOD, Merlion, darts, Anomalib, Telemanom, foundation-модели
MOMENT/Chronos/TimesFM).
